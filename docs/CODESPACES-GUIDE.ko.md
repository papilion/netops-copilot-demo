# NetOps Copilot — Codespaces 사용법 (처음 쓰는 사람용)

이 문서는 GitHub Codespaces로 NetOps Copilot 라이브 데모를 보는 방법을
처음부터 끝까지, 클릭 순서대로 적었습니다. 로컬 설치, WSL, 자바 직접
설치는 필요 없습니다. 필요한 것은 GitHub 계정과 브라우저뿐입니다.

## 0. Codespaces가 뭔가요?

Codespaces는 GitHub 클라우드 서버 안에 만들어지는 개발용 컴퓨터입니다.
저장소를 열면, 파이썬·자바·Batfish까지 갖춰진 환경이 브라우저에서
열립니다. 내 PC에 아무것도 설치하지 않아도 됩니다. 단, 이 컴퓨터는
내 계정 전용입니다. 저장소가 공개(public)라도, 내 Codespace를 다른
사람이 열거나 시작할 수는 없습니다. 다른 사람이 써보려면 자기 계정으로
자기 Codespace를 새로 만들어야 하고, 그 비용은 그 사람 계정에서 나갑니다.

## 1. 처음 만들기 (10~15분 걸립니다)

1. GitHub 웹에서 저장소를 엽니다.
   `https://github.com/papilion/netops-copilot-demo`
2. 초록 **Code** 버튼 → **Codespaces** 탭 → **Create codespace**를
   누릅니다. (브랜치는 `main`입니다.)
3. 설정이 끝날 때까지 기다립니다. **처음 만드는 데는 10~15분이
   정상 범위**입니다. VM 준비, 개발 컨테이너 빌드, Batfish 이미지
   다운로드, Batfish 기동·파싱이 차례로 돌아가기 때문입니다.
4. 만드는 동안 창을 닫아도 됩니다. 만들기는 서버에서 계속 진행되고,
   나중에 Codespaces 목록에서 다시 열면 됩니다.
5. **+를 여러 번 누르지 마세요.** +를 누를 때마다 새 Codespace가
   처음부터 만들어져서, 기다린 시간이 리셋됩니다.

### 만드는 도중 로그 보기

만들기 화면에서 진행 상황이 멈춘 것처럼 보이면, 키보드에서
`Cmd/Ctrl + Shift + P`를 누르고 **View Creation Log**를 선택하세요.
어디에서 멈췄는지(예: 이미지 다운로드 중, Batfish 기동 중) 보입니다.
`Running postStartCommand... bash scripts/start-live.sh` 단계는
Batfish가 준비될 때까지 기다리는 단계라, 몇 분간 스피너만 도는 것이
정상입니다. 스크립트는 30초마다 경과를 찍습니다.

## 2. 웹 앱 열기 (지구본 아이콘)

1. Codespace가 열리면, 아래쪽 **PORTS** 탭을 클릭합니다.
   안 보이면 상단 메뉴 View > Ports, 또는 `Cmd/Ctrl + Shift + P`에서
   "Ports: Focus on Ports View"를 선택합니다.
2. 포트 **8000** 줄을 찾습니다. (이름: NetOps Copilot web app)
3. 그 줄 오른쪽의 **지구본 아이콘**("Open in Browser")을 클릭합니다.
   웹 앱이 새 브라우저 탭으로 열립니다. 지구본이 안 보이면, 8000 줄을
   우클릭하고 "Open in Browser"를 선택합니다.
4. 포트 8000의 공개 상태는 **Private**으로 두세요. 지구본을 눌렀다고
   공개가 되는 것이 아닙니다. Private 주소도 내 GitHub 로그인으로만
   열립니다.

### 포트 2개가 보이면?

- **8000만 보이면 정상**입니다. 최신 설정은 8000만 전달합니다.
- **9996이 같이 보이면 옛 Codespace**입니다. 9996은 Batfish 내부
  API 포트라, 브라우저로 열면 404가 뜹니다. **404가 정상**입니다.
  Batfish가 듣고 있다는 뜻이고, 라이브가 고장난 것이 아닙니다.
  라이브는 8000 하나로만 동작합니다. 웹 앱이 Codespace 안에서
  9996으로 Batfish와 얘기합니다.

## 3. 라이브 시나리오 돌리기

1. 웹 앱 위쪽에서 **언어**를 고릅니다. 한국어 / English 중 선택하면
   화면 글자와 설명 언어가 바뀝니다.
2. **토폴로지**를 고릅니다. 단순 데모(5 nodes) 또는 고급 랩(13 nodes).
3. **시나리오**를 고릅니다. 구성도에서 테스트 구간이 표시됩니다.
   - **빨간 점선(애니메이션)** = 테스트 대상 구간
   - **초록 점선** = 우회 경로 또는 새 출구
   - 노드 아래에는 **ASN과 IP**가 표시됩니다. 내부는 Loopback,
     외부는 발표 prefix이며, 모두 실제 랩 설정에서 가져온 값입니다.
4. 모드에서 **Live**를 선택하고 **검증 실행 / Run validation**을
   누릅니다. Recorded replay는 Batfish 없이 기록 재생으로 동작합니다.
5. 결과는 위에서 아래로 이렇게 읽습니다.
   - **판정**: 🟢 ALLOW(바꿔도 됨) / 🟡 REVIEW(사람 확인) /
     🔴 BLOCK(바꾸면 안 됨)
   - **한눈에 보기**: 끊긴 것, 변경 없음 개수, Control/Protected
     비교가 세 줄로 나옵니다. RPKI처럼 Control run과 Protected run이
     있는 시나리오는, route-map이 무효 발표를 막았는지 이 한 줄로
     확인합니다.
   - **설명 / 제안하는 다음 단계**: 판정 뒤에 오는 설명과 제안입니다.
   - **변경된 증거**: 끊긴 경로·flow만 표로 나옵니다.
   - **CLI 형태 보기**: 접혀 있습니다. 필요할 때만 펼치세요.
     Batfish 증거를 CLI 형태로 그린 것이지, 실제 라우터 출력이
     아닙니다.

### 판정에 대하여 (중요)

판정은 **Batfish 증거로만** 정해집니다. AI는 판정을 내리지 않습니다.
AI는 판정 뒤에 설명과 제안을 다듬는 역할만 합니다. 출처 표시를 보세요.

- 설명 출처가 `Meta Model API`이면, 모델이 증거를 보고 쓴 설명입니다.
- 설명 출처가 `local-template (no API call)`이면, 키가 없어서
  미리 정해둔 문장으로 설명한 것입니다.
- 제안 출처가 `Meta Model API (refined from rule-based proposal)`이면,
  모델이 규칙 기반 제안을 다듬은 것입니다.

## 4. 다시 열기, 멈추기, 지우기

### 다시 열기 (기존 Codespace 클릭, + 아님)

- 저장소 → Code → Codespaces 탭에서, **기존 Codespace 이름을
  클릭**합니다. 클릭 자체가 시작입니다. 별도 ▶ 시작 버튼은 없습니다.
- 또는 이름 옆 **...** 메뉴에서 **Start codespace**를 선택합니다.
- https://github.com/codespaces 목록에서도 마찬가지입니다.
- **기존 것을 다시 시작하면 2~5분이면 됩니다.** 새로 만드는
  10~15분과 다릅니다. 그래서 만든 Codespace는 지우지 말고 계속
  쓰는 것이 빠릅니다.

### 멈추기

- 브라우저 탭만 닫는다고 바로 꺼지지 않습니다. 한동안 안 쓰면
  기본 30분 유휴 후에 자동으로 멈춥니다.
- 직접 멈추려면, Codespaces 목록에서 해당 Codespace 옆 **...** →
  **Stop codespace**를 선택합니다.
- 멈추는 데는 보통 1분 이내가 걸립니다. 오래 "Stopping..."으로
  보이면, 브라우저를 새로고침(F5)하고
  https://github.com/codespaces 에서 상태를 확인하세요.

### 지우기

- Codespaces 목록에서 **...** → **Delete**를 선택합니다.
- **주의**: 지우기 전에, 그 Codespace 안에 커밋 안 한 변경이 있는지
  터미널에서 `git status`로 확인하세요. 커밋 안 한 작업은 삭제하면
  사라집니다. 커밋된 내용은 저장소에 이미 있으니 안전합니다.
- Codespace 이름(`dark crematorium` 같은)은 GitHub이 랜덤으로
  붙이는 이름이라 의미가 없습니다. 포트 개수로 새것/옛것을 구분하세요.

## 5. 요금 (개인 계정 기준)

- GitHub Free 개인 계정은 매달 **120 core-hours + 저장공간 15GB**가
  무료입니다. GitHub Pro는 180 core-hours + 20GB입니다.
- 계산 시간은 코어 수 × 켜져 있는 시간입니다. 2코어 Codespace를
  1시간 켜면 2 core-hours가 소모되므로, Free 한도는 2코어 기준
  **실제 60시간**입니다.
- 계산 요금은 **켜져 있을 때만** 나갑니다. 멈춘 상태는 계산 요금이
  없습니다. 저장공간 요금은 Codespace가 존재하는 동안(멈춰 있어도)
  계속 나갑니다. 다만 이 데모 저장소는 작아서, 15GB 한도 안에
  넉넉히 듭니다.
- 결제 수단을 등록하지 않았다면, 한도를 다 쓰면 사용이 그냥
  막힙니다. 자동으로 돈이 나가지는 않습니다. 결제 수단을 등록하고
  한도를 넘기면, 그때부터 유료입니다. (2코어 기준 시간당 $0.18,
  저장공간 GB당 월 $0.07 수준입니다.)
- 두 개를 둘 다 켜두면 계산 시간이 두 배로 소모되니, 안 쓰는 쪽은
  Stop이나 Delete를 하세요.
- 사용량은 GitHub 설정 → Billing에서, Codespace 목록은
  https://github.com/codespaces 에서 확인합니다.

## 6. 지역 (한국 데이터센터는 없습니다)

- Codespace 지역은 기본적으로 위치 기준으로 자동 정해집니다.
  한국에서 가장 가까운 선택지는 동남아시아(싱가포르)입니다.
  한국 데이터센터는 없습니다.
- 설치 다운로드 속도는 집 인터넷 속도가 아니라, Codespace 서버의
  인터넷 속도입니다. 한국이라서 설치가 느려지는 구조가 아닙니다.
- 지역을 직접 고정하고 싶으면, GitHub 프로필 → Settings →
  Codespaces → Region에서 Set manually로 바꾸고 Southeast Asia를
  선택하세요.

## 7. Meta AI 설명 켜기 (선택 사항)

키가 없어도 판정과 라이브 검증은 전부 동작합니다. AI 설명만
규칙 기반 문장으로 나옵니다. 진짜 Meta AI 설명을 보려면:

1. dev.meta.ai에서 API 키를 확인합니다. **키를 채팅이나 저장소에
   붙여넣으면 안 됩니다.**
2. GitHub 웹에서 저장소 → Settings → Secrets and variables →
   Codespaces → New codespace secret을 만듭니다. 이름은
   `META_API_KEY`, 값은 키입니다.
3. Codespace를 Stop했다가 다시 시작합니다. 이미 켜진 앱은 키를
   못 읽습니다.
4. 다시 Live로 돌리면, 설명 출처가 `Meta Model API`로 바뀝니다.
- 빠르게 한 번만 시험해보고 싶으면, Codespace 터미널에서 키를
  export한 뒤 웹 앱을 다시 켜는 방법도 있습니다. 다만 이건
  Codespace를 끄면 사라지고, 터미널 기록에 키가 남으니, 정석은
  위 Secrets 방법입니다.
- 키를 켜도 판정은 바뀌지 않습니다. 판정은 여전히 Batfish 증거로만
  정해집니다. 모델이 쓰는 토큰 비용은 시나리오당 1센트 수준으로
  매우 작습니다.

## 8. 문제 해결 (자주 묻는 증상)

| 증상 | 원인 / 해결 |
|---|---|
| 구성도·시나리오 선택이 전혀 안 나옴 | 옛 자바스크립트가 캐시에 남아 있거나, 코드를 안 받은 경우입니다. Codespace 터미널에서 `git pull` 후, 브라우저 **강제 새로고침(Ctrl+Shift+R)**을 하세요. 그래도 안 되면 웹 앱을 다시 켜세요. (`pkill -f "web/app.py"` 후 `bash scripts/start-live.sh`) |
| Live에서 503이 뜸 | Batfish가 아직 준비 안 된 것입니다. 잠시 기다렸다가 다시 실행하거나, 터미널에서 `bash scripts/start-live.sh`를 돌리세요. 그래도 안 되면 `docker logs batfish`를 확인하세요. |
| postStart에서 오래 멈춘 것처럼 보임 | Batfish 기동·파싱 중일 수 있습니다. View Creation Log로 어디에서 멈췄는지 확인하세요. 처음 만드는 경우 10~15분까지 갈 수 있습니다. 20~25분이 넘었는데도 같은 줄에서 안 움직이면, Stop 후 다시 시작을 한 번 해보세요. |
| 포트 9996을 열면 404 | 정상입니다. 9996은 웹 페이지가 아니라 Batfish 내부 API입니다. 8000만 여세요. |
| 매번 설치가 반복됨 | 기존 Codespace를 다시 연 것이 아니라, 새 Codespace를 만들고 있는 것입니다. +가 아니라 기존 이름을 클릭하세요. |
| 설명이 규칙 기반 문장만 나옴 | 키가 없는 것입니다. 위 7번 Secrets 방법을 따르세요. |
| 시작 아이콘이 안 보임 | 별도 시작 버튼이 없습니다. Codespace 이름을 클릭하는 것이 시작입니다. |

## 9. 안전 수칙 (반드시 지키세요)

- 이 데모 서버는 로컬 전용(127.0.0.1)이며 인증이 없습니다.
  포트 8000을 **Public으로 바꾸지 마세요.**
- 데모 데이터는 전부 가짜입니다 (RFC 5737, AS 64496–64501).
  실제 운영 설정, 실제 고객 prefix, 실제 회사 설정을 공개 데모에
  붙여넣지 마세요.
- API 키, 비밀번호를 저장소 파일, 채팅, 화면 캡처에 넣지 마세요.
  키는 Codespaces Secrets로만 관리합니다.
- 이 도구는 판정만 내립니다. 설정을 라우터에 적용하지 않으며,
  최종 결정은 사람이 합니다. 판정은 감시 범위 내에서만 유효합니다.

## 10. 빠른 요약 (한 번만 읽으면 됩니다)

1. Code → Codespaces → Create codespace (처음 10~15분)
2. PORTS 탭 → 포트 8000 지구본 클릭 (Private 유지)
3. 언어 선택 → 토폴로지 선택 → 시나리오 선택 → Live → 검증 실행
4. 판정 → 한눈에 보기 → 설명·제안 순서로 읽습니다
5. 다음부터는 기존 Codespace 이름 클릭 (2~5분), +는 새로 만들기입니다
